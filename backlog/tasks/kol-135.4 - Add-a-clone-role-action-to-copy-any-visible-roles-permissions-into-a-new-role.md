## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Add a 'Clone' action on the Roles screen for any role a user can currently view (admin/employee/supervisor/custom) — not for dt/saas, which stay fully hidden. Cloning creates a new, ordinary (non-system) role pre-populated with the source role's current permissions, named '<Original> (copy)' (deduplicated, e.g. '(copy 2)', if that name is already taken), and the user lands on it able to rename and adjust it immediately like any custom role created via KOL-135.2.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Cloning a role (system or custom) creates a new role with identical permissions to the source role at the moment of cloning
- [x] #2 The cloned role defaults to the name '<Original> (copy)', deduplicated if that name already exists
- [x] #3 The cloned role is always a normal custom role, even when cloned from admin/employee/supervisor, so it can be freely renamed and deleted afterward
- [x] #4 No clone action is available for dt/saas roles
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Backend: add RoleController::clone(Role) - abort 403 for PROTECTED_ROLES (dt/saas), create a new Role named '<Original> (copy)' deduped via ' (copy N)' suffix, syncPermissions from source role's current permissions, redirect to roles.show like store().
2. Add POST roles/{role}/clone route -> roles.clone, inside the existing Manage:Role middleware group.
3. Regenerate Wayfinder (php artisan wayfinder:generate --with-form) so resources/js/routes/roles/index.ts exposes clone().
4. Frontend: add a Clone action to roles/index.tsx row actions (via DataTableRowActions children, Copy icon) that posts to clone(role.id).url and preserves scroll; shown for every visible row (dt/saas already excluded from the index query, satisfying AC4).
5. Add ui.roles.actions.clone and ui.roles.flash.cloned translations (en+es).
6. Pest tests in RoleManagementTest.php: clone copies permissions, dedupes name (existing '(copy)' -> '(copy 2)'), clone of a system role produces a normal renameable/deletable role, dt/saas clone forbidden, non-admin forbidden, redirects to the new role's show page.
7. Run pint --dirty, sail artisan test --compact --filter=RoleManagementTest, npm run types:check.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Verified via filtered tests only (RoleManagementTest, RolePresenterTest, RolesPermissionsTest — 66 tests, all passing); full suite deferred per standing user preference until reviewed.

code-review (medium) surfaced a name-length overflow risk (cloning a role near the 255-char limit could exceed the roles.name column and throw an unhandled QueryException) — fixed with truncatedCloneName() and covered by a new test. Left the reported check-then-create race on the dedup name unaddressed: store()/update() have the same TOCTOU gap via Rule::unique and it's never guarded elsewhere in this codebase, so guarding only the new clone path would be inconsistent with existing conventions.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Added a Clone row action to the Roles index (visible for every row shown — dt/saas are already excluded from that query, satisfying AC4 with no extra guard) that POSTs to a new roles/{role}/clone route. RoleController::clone() 403s on PROTECTED_ROLES, creates a new plain Role named '<name> (copy)' (deduped to '(copy 2)', '(copy 3)', ... and truncated to fit the 255-char column), copies the source role's current permissions via syncPermissions(), and redirects to the clone's show page — landing the admin on it ready to rename/adjust, same as store(). Verified with 6 new Pest tests in RoleManagementTest.php (permission copy, dedup, name-length truncation, system-role clone stays renameable/deletable, protected-role clone forbidden, non-admin forbidden) plus the existing RoleManagementTest/RolePresenterTest/RolesPermissionsTest suites (66 tests, all passing), vendor/bin/pint --dirty clean, and npm run types:check clean.
