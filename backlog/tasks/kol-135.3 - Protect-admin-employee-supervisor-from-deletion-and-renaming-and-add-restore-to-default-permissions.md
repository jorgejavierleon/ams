## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Add a 'system role' concept for admin/employee/supervisor — distinct from RolePresenter::PROTECTED_ROLES (dt/saas), which stay fully hidden/uneditable. System roles remain visible and their permissions remain fully editable (per KOL-133), but: they cannot be deleted via the delete action added in KOL-135.2, their name cannot be changed via the rename support added in KOL-135.2, and a 'Restore to default permissions' action resyncs their permissions to the RoleSeeder::EMPLOYEE_PERMISSIONS / SUPERVISOR_PERMISSIONS / ADMIN_PERMISSIONS constants — the permanent source of truth for 'system default', changed only via a code deploy.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Attempting to delete the admin, employee, or supervisor role is rejected (no route or UI path succeeds)
- [ ] #2 Attempting to rename the admin, employee, or supervisor role is rejected; their permissions remain editable
- [ ] #3 A 'Restore to default permissions' action is available on admin/employee/supervisor and resyncs the role's permissions to exactly the corresponding RoleSeeder constant
- [ ] #4 dt/saas remain fully excluded from the Roles screen as before, with no new exposure
- [ ] #5 Custom (non-system) roles are unaffected: they can still be freely renamed and deleted per KOL-135.2
