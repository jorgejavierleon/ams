## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Since KOL-133.4, employees.* routes are gated by View:Employee/Manage:Employee permissions instead of role:admin. The shared Inertia prop auth.isAdmin (HandleInertiaRequests.php) still checks the admin role name, and several list pages (leaves, overtime pacts, overtime rest-day-balances, overtime requests, workdays, documents) use it to decide whether to render a link to an employee's show page. This drifts from actual route access once an org edits the admin role's permissions or grants View:Employee to a different role via the Roles screen: a role stripped of View:Employee would still see a link that 403s, and a role granted View:Employee wouldn't see the link at all.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Rename the shared Inertia auth prop in HandleInertiaRequests.php from isAdmin (hasRole('admin')) to canViewEmployee (hasAnyPermission(['View:Employee','Manage:Employee'])).
2. Update resources/js/types/auth.ts Auth type: isAdmin -> canViewEmployee.
3. Replace auth.isAdmin with auth.canViewEmployee in the 6 list pages: leaves/index.tsx, workdays/index.tsx, documents/index.tsx, overtime/pacts/index.tsx, overtime/rest-day-balances/index.tsx, overtime/requests/index.tsx (JSX href guards and useMemo deps).
4. Update/replace the existing auth.isAdmin Pest coverage: LayoutTest.php (shared-prop test, now covering a non-admin role granted View:Employee and admin stripped of View:Employee) and SupervisorLeaveApprovalTest.php (rename assertion + comment).
5. Verify: pint --dirty, targeted Pest filters (LayoutTest, SupervisorLeaveApprovalTest, EmployeeManagementTest, LeaveManagementTest, DocumentSignatureWorkflowTest, DashboardActionItemsTest, LeaveQueueBadgeTest, OvertimeQueueBadgeTest, ShiftAssignmentManagementTest), npm run types:check.
