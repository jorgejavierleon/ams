## Implementation Notes

Added BlogPost entry (slug: resolucion-38-direccion-del-trabajo-como-cumplir) in app/Support/Blog/BlogPosts.php and its page resources/js/pages/blog/posts/resolucion-38-direccion-del-trabajo-como-cumplir.tsx, following the KOL-145.1 post pattern exactly (BlogPostLayout, BlogPostMeta props). Every legal claim was checked against docs/context/resolucion_38.txt directly (read the full 862-line text): scope (Art. 2, Art. 3n — electronic systems only, incl. messaging apps used for marking), per-mark requirements (Art. 8 hash/checksum, Arts. 9-10 automatic transmission + offline exception, Arts. 12-13 voucher content), access rules (Art. 22.1 worker 5-year history, Art. 22.2 employer admin profile, Arts. 39-41 modification/48h objection window, Art. 17/22.4 DT 24/7 portal), the Art. 27 mandatory reports (asistencia, jornada diaria, domingos/festivos, modificaciones de turno, incidentes técnicos — all five already implemented in app/Http/Controllers/Dt/ReportController.php with matching Art. 27 code comments), overtime compensation (Art. 43) and the rest-day accrual/expiry alert (Art. 45.3, already implemented as app/Console/Commands/NotifyRestDayBalances.php), and non-compliance consequences (Art. 49). The 'Cómo Kolvi ayuda' closing section only claims features that exist in the codebase (folio voucher, DT report exporter) — it does not claim DT authorization/certification, since nothing in the repo evidences that status.

Updated tests/Feature/BlogTest.php to generalize from one hard-coded post to iterate BlogPosts::all() via Pest ->with(), so the suite scales with future posts instead of needing a new hand-written test per post.
