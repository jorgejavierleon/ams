## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Builds on KOL-137.1 (email volume is now visible). This slice lets a platform admin set the per-organization caps that KOL-137.3 will enforce — still no enforcement in this ticket.

Add one platform-wide, admin-editable setting: expected emails per user per month (the "baseline"). No default value is being prescribed by this ticket — ship the setting with whatever safe placeholder makes sense (e.g. unset/0 until an admin sets it), not a guessed number.

Each organization gets two independent monthly figures, **soft limit** and **hard limit**:
- When not explicitly overridden for that organization, both default to `active_users_count × baseline`.
- A platform admin can override either figure independently, per organization, from the SaaS organization page.
- An override is sticky: changing the platform-wide baseline later recalculates defaults only for organizations that have never been overridden on that figure; existing overrides are untouched.

Reference: `App\Models\Organization`, `App\Http\Controllers\Saas\OrganizationController`, `App\Enums\Plan` (limits are per-organization, not per-plan — do not key this off Plan).

## User stories for manual testing (Gherkin)

```gherkin
Feature: Configure monthly email limits per organization

  Scenario: Limits default from the platform baseline
    Given the platform baseline is set to 10 expected emails per user per month
    And organization "Acme" has 8 active users and no limit overrides
    When a platform admin opens Acme's email limits in the SaaS panel
    Then both the soft limit and the hard limit show 80

  Scenario: A platform admin overrides one organization's limit
    Given organization "Acme" currently shows an 80 soft limit
    When a platform admin sets Acme's soft limit to 50 and saves
    Then Acme's soft limit is 50
    And organization "Beta", which was not touched, still shows its own calculated default

  Scenario: Changing the baseline respects existing overrides
    Given organization "Acme" has an overridden hard limit of 120
    And organization "Beta" has never had its hard limit overridden
    When a platform admin changes the platform baseline from 10 to 15
    Then Acme's hard limit remains 120
    And Beta's hard limit recalculates using the new baseline of 15
```
