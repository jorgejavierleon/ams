## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The landing page (resources/js/pages/landing.tsx) has six feature rows plus a 'cómo funciona' and pricing section between the hero CTA and the only other conversion point at the very bottom (#demo). A visitor who decides to convert partway through the feature rows currently has no nearby way to act and must scroll past several more sections. Add a secondary, lower-commitment conversion entry point positioned after the feature rows (or as a persistent element) so engaged scrollers aren't forced to reach the footer.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Insert a new CTA band section in resources/js/pages/landing.tsx right after the feature rows section (id=funciones) and before the 'cómo funciona' section — closest point to where an engaged scroller finishes reading features.
2. Style it distinctly from the bottom #demo band (lighter bg-muted/30 band with heading + short copy + single button) rather than reusing the primary-colored band or duplicating the email form.
3. Button links via a plain anchor <a href="#demo"> (same pattern already used by the header/hero/planes CTAs) so it scrolls to the existing #demo section and form — no new route, no duplicate backend wiring.
4. Make it responsive: stacked/centered on mobile, same max-w-* container pattern as sibling sections.
5. Run npm run types:check and sa test --compact (LandingPageTest) to confirm nothing broke. No PHP touched, so no new Pest test needed.
