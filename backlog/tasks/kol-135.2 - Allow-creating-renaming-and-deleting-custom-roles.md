## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
RoleController (app/Http/Controllers/RoleController.php) currently only exposes index/show/update (permissions-only edit) — there is no way to create a new role, rename one, or delete one. Add a 'New role' flow (name + permission selection) and delete support, gated by the existing Manage:Role permission like the rest of the Roles screen. Deleting a role that is currently assigned to one or more users must warn how many users will lose that role, and proceed to detach it from them on confirmation (force-unassign, not a hard block). Role names must stay unique (existing Spatie roles.name+guard_name constraint).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A user with Manage:Role can create a new role with a name and an initial set of permissions from the Roles screen
- [x] #2 A user with Manage:Role can rename a role and edit its permissions after creation
- [x] #3 A user with Manage:Role can delete a role; if the role is currently assigned to any users, a confirmation step shows how many users will lose the role before deletion proceeds
- [x] #4 Deleting a role removes it and detaches it from every user who held it, without deleting those users or their other roles
- [x] #5 Creating or renaming a role to a name that already exists shows a validation error instead of a server error

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Routes (routes/web.php): add GET roles/create, POST roles (store), DELETE roles/{role} (destroy) inside the existing Manage:Role group, registering roles/create before roles/{role} to avoid the wildcard swallowing it.
2. RoleController: extract a private permissionGroups(?Role $role) helper (used by show() and create()) from the existing grouping logic. Add create() (renders roles/create with empty-assigned permission groups), store() (validate name unique+permissions, Role::create + syncPermissions, redirect to show), destroy() (abort_if PROTECTED_ROLES, detach role from all users via $role->users()->detach(), delete role, redirect to index). Extend update() to also validate+apply a unique `name` field alongside permissions.
3. Add Rule::unique('roles','name')->where('guard_name','web') (ignore current role on update) for name validation on both store and update.
4. Frontend: extract shared permission-group grid markup from roles/show.tsx into resources/js/components/role-permission-groups.tsx; add resources/js/pages/roles/create.tsx (name input + shared grid, posts to roles.store); add a name Input to roles/show.tsx (submitted together with permissions to roles.update).
5. roles/index.tsx: add a "New role" button linking to roles.create, and replace the plain "Manage" link column with DataTableRowActions (view -> show, delete -> ConfirmDialog using the row's already-known users_count for the warning copy, no extra request needed).
6. Lang files (lang/en/ui.php, lang/es/ui.php): add ui.roles.new, ui.roles.form.name(+placeholder), ui.roles.create_dialog/delete_dialog copy, ui.roles.flash.created/deleted/updated keys.
7. Regenerate Wayfinder (npm run build or dev) so resources/js/routes/roles + actions/.../RoleController pick up create/store/destroy.
8. Pest tests in tests/Feature/RoleManagementTest.php: create (success, duplicate name validation, permission gating), rename+edit permissions together, delete without users, delete with users (detach, users keep other roles, users not deleted), delete is gated by Manage:Role and blocked for protected roles.
9. Run vendor/bin/pint --dirty --format agent, sail artisan test --compact --filter=RoleManagement, npm run types:check.

## Implementation Notes

Extracted permissionGroups(?Role) helper shared by show()/create(). destroy() detaches the role from all users (globally, since roles are shared across orgs) then deletes it; still gated by the existing PROTECTED_ROLES abort_if (dt/saas). Verification:

Code review (medium, forked agent): 2 findings.
1. destroy()/update() only guard PROTECTED_ROLES (dt/saas) - deleting/renaming admin/employee/supervisor is unguarded. Proceeding to KOL-135.3 immediately per that decision.

Added deleting state wired through router.delete's onStart/onFinish, passed as processing to ConfirmDialog (matches the pattern in dashboard.tsx).
