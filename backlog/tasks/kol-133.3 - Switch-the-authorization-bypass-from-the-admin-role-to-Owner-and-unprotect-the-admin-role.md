## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Move the blanket authorization bypass off the admin Spatie role and onto the new Owner concept, then remove the protections that currently exist only because the admin role used to be the unconditional bypass.

Changes:
- Gate::before in AppServiceProvider checks Owner instead of hasRole('admin').
- RolePresenter::PROTECTED_ROLES drops 'admin' (dt and saas stay protected); the admin role becomes editable and assignable/removable like any other role, including to/from the Owner.
- RoleController/RolePresenter allow editing the admin role's permission set (currently excluded from the editable list).
- The ad hoc hasRole('admin') checks used for "see everything vs. only my team" scoping (DashboardController, OvertimeRequestController, LeaveController, LeaveCalendarController, HandleInertiaRequests, app/Mcp/Tools/Leave/ViewTeamLeavesTool) are updated to also account for the Owner, so an Owner without the admin role still sees organization-wide data.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Discovered mid-implementation that flipping Gate::before to Owner-only breaks non-owner admin access far beyond the 6 named files (every Policy ability admin previously reached only via the blanket Gate::before bypass: Leave/OvertimeRequest approve-reject, Workday index/update/view/approve/revoke). Asked user how to scope it; decision: flip Gate::before strictly to isOwner() as described, do not add admin-role fallbacks to Policies, and fix affected tests by making the test's admin actor also the organization Owner.

Fixed ~15 test files whose admin helper needed Owner status: LeaveManagementTest, LeaveCalendarTest, LeaveWorkdayRecalculationTest, OvertimeSectionTest, SupervisorLeaveApprovalTest, WorkdayManagementTest, WorkdayOvertimeTest, Mcp/Leave/LeaveToolsTest, EmployeeManagementTest (pacto/manageOvertimePacts scenarios). Updated RoleManagementTest + EmployeeManagementTest for admin no longer being a protected role.

Verified with: vendor/bin/pint --dirty --format agent (clean); full sail artisan test --compact run twice solo (1551 passed, 7 pre-existing skips, 0 failures). An earlier full-suite attempt showed spurious table-exists/missing errors from an unrelated concurrency issue (my own overlapping background test invocations), not a real regression - confirmed by a clean solo re-run.

Incident: accidentally ran 'sail artisan migrate:fresh --env=testing --force' which (no .env.testing existing) actually wiped the main dev database (ams), not the test DB. Disclosed to user; they said no recovery needed.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Gate::before now grants full access based on Organization Owner (User::isOwner()) instead of the admin Spatie role; RolePresenter::PROTECTED_ROLES dropped 'admin' (dt/saas remain protected), making the admin role's permissions freely editable via the existing Roles screen with no code changes needed in RoleController. The 6 ad hoc hasRole('admin') scoping checks (DashboardController's 3 widgets, OvertimeRequestController::index, LeaveController::index, LeaveCalendarController::events, HandleInertiaRequests::pendingLeaveRequestsCount, ViewTeamLeavesTool) now also check isOwner() so an Owner without the admin role sees organization-wide data instead of being scoped like a lone supervisor. Per explicit user decision, Policies were left untouched, so a non-owner admin loses whatever access it previously got only through the blanket Gate::before bypass outside those 6 files (Leave/Overtime approve-reject, Workday screens) - existing tests exercising that were updated to make the admin actor also the Owner. Added new Pest coverage for AC5 (OrganizationOwnershipTest, plus an Owner-without-admin-role regression test alongside each of the 6 touched files' existing admin coverage). Verified: pint clean, full suite green (1551 passed / 7 pre-existing skips) run twice solo.
