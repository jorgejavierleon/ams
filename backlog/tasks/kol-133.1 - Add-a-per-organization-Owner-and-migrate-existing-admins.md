## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Add an owner concept to Organization: a single user who unconditionally bypasses every authorization check within that organization, independent of any Spatie role/permission they hold. This is the foundation subtask other work in KOL-133 depends on.

Migrate existing data: for each organization, the earliest-created user (by created_at) currently holding the admin Spatie role becomes that organization's owner. Organizations with no admin user today are left without an owner (to be resolved manually or by a future flow) rather than guessing.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Migration `add_owner_id_to_organizations_table`: nullable `owner_id` foreignId on `organizations`, constrained to `users`, restrictOnDelete (DB-level guard against deleting a user who is currently an owner, complementing the app-level guard KOL-133.2 will add). Same migration backfills owner_id: for each organization, the earliest-created user (users.created_at) holding the Spatie `admin` role becomes owner_id, via a raw query over model_has_roles/roles/users (no Eloquent models in the migration, matching existing migration style). No down() (irreversible data migration, matches repo convention).
2. Organization model: add `owner_id` to the PHPDoc block (NOT added to #[Fillable] — ownership must only change through a dedicated transfer action in KOL-133.2, never generic mass assignment) and an `owner(): BelongsTo` relation.
3. User model: add `isOwner(): bool` — the single source of truth Gate::before will call in KOL-133.3. Implemented as `$this->organization_id !== null \&\& $this->organization?->owner_id === $this->id`.
4. OrganizationFactory: add an `ownedBy(User $user)` state (forceFill + save in afterCreating) so tests can set ownership without exposing owner_id via mass assignment.
5. Pest tests (tests/Feature/OrganizationOwnershipTest.php): migration backfill picks the earliest of several admins per org; an org with no admin user is left with owner_id null; User::isOwner() true for the owner, false for a non-owner admin and for a user in a different organization.
6. vendor/bin/pint --dirty --format agent, then sa test --compact --filter=OrganizationOwnership (and the wider affected suite) before wrapping up.

Out of scope (flagging, not building): Saas\OrganizationController::store creates an organization with no owner and no initial user — nothing today assigns an owner when a brand-new tenant is created via the SaaS panel. That gap is not covered by this subtask's acceptance criteria (which only require backfilling existing orgs); worth a follow-up task once KOL-133.2/.3 land.
<!-- SECTION:PLAN:END -->
