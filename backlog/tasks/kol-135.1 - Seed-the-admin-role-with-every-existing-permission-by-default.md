## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
RoleSeeder::ADMIN_PERMISSIONS (database/seeders/RoleSeeder.php) is a curated list that is missing most EMPLOYEE_PERMISSIONS and all SUPERVISOR_PERMISSIONS, so a freshly seeded admin role is not actually 'all permissions' today. Admin should be seeded with the full permission set the seeder knows about (union of Employee + Supervisor + Admin-specific permissions), while remaining a fully editable role per KOL-133 — an organization can still strip permissions from admin afterward via the Roles screen; this is a one-time default, not a live/enforced invariant. This default also becomes the restore target used by the system-role restore action in a sibling subtask.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Change RoleSeeder::run() to grant admin the union of EMPLOYEE_PERMISSIONS + SUPERVISOR_PERMISSIONS + ADMIN_PERMISSIONS instead of ADMIN_PERMISSIONS alone.
2. Keep the ADMIN_PERMISSIONS constant itself unchanged (and document why) since HandleInertiaRequests::effectivePermissionNames() relies on it NOT including employee-only permissions (e.g. ViewOwn:Leave) to keep the Owner's synthetic nav permissions from tripping the frontend's isEmployee check.
3. Add a regression test asserting admin holds every permission the seeder defines (not just the old ADMIN_PERMISSIONS subset), including former gaps like RequestOwn:Leave, ViewTeam:Leave, ApproveTeam:OvertimeAuthorization.
4. Run pint and the affected Feature tests (RolesPermissionsTest, RoleManagementTest, OrganizationOwnershipTest, MarkTest, LeaveToolsTest).
<!-- SECTION:PLAN:END -->
